03 / Everyday work

Start with a question.
Leave a trail.

Three practical uses for the existing local tools. The connected experience is still being refined.

01 — RESEARCH

Find the source again.

Move from a research question to relevant notes and source references. Keep uncertainty visible when the evidence is incomplete.

  1. Question → notes → source
  2. Record the finding and its limits
02 — CONTINUE

Resume the thread.

Return to an agent session, inspect its project context and history, then choose the next action from the operator workspace.

  1. Project → session → history
  2. Continue with the right context
03 — REVIEW

Check what changed.

Inspect changes and recorded checks before accepting a result. Keep an agent’s completion message separate from verification.

  1. Change → check → review
  2. Accept, investigate, or repair

04 / Project status · 19 October 2026

Real software.
A clear view of its limits.

Macrothought is an independent, operator-managed workspace project. The local tools are substantial; a reproducible public release and a consistent end-to-end experience still need work.

Working locally

The current foundation

  • Managed remote agent sessions and session history.
  • Markdown memory, map exploration, and research tools.
  • Project and change history, checks, and provenance records.
Isolated previews

Being brought together

  • Independently reviewed department focus and responsive map fixes.
  • Draft preservation, source navigation, and evidence views in a newer isolated UX candidate.
  • Preview acceptance does not establish live deployment; newer UX work still needs independent review.
Experimental

Bounded, still evaluated

  • Agent deliberation, governance, and optional model adapters.
  • Source extraction and provider paths with varying coverage.
  • No autonomous security guarantee or verified multi-user enforcement.
Roadmap

A coherent shared workspace

  • Galaxy, department, project, and file views linked by stable identities.
  • Clearer agent activity and evidence across those views.
  • Reproducible releases, access validation, and usability evaluation.

“Working locally” reflects inspected source and prior local evaluations, not a production certification. A connected Sol chat bridge, production-ready OS, live trading, and customer adoption are not established.

05 / How it fits together

Plain-text roots.
Connected views.

Consulate combines a Python core, browser interfaces, Markdown knowledge, and separate stores for relationships and operational records.

A shared interface can reference those records without putting every kind of data into one database. Optional local and cloud model tools depend on explicit configuration.

01

Knowledge & relationships

Markdown notes hold durable knowledge. Entity records and source references describe the connections.

02

Work & evidence

Sessions, requirements, artifacts, checks, and reviews retain different roles and records.

03

Views & operator choices

Maps, project views, history, and research surfaces make those records inspectable. Bounded controls support human review; governance remains under evaluation.
